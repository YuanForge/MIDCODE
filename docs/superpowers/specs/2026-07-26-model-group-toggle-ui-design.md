# 模型分组启停操作设计

## 目标

在管理端“模型分组”页面补充明确的停用与重新启用操作。复用现有模型分组状态字段和切换接口，不新增数据库迁移或后端路由。

## 交互

- 在每个分组的“操作”列显示状态操作按钮。
- 启用中的分组显示“停用”；点击后先确认，确认后调用现有切换接口。
- 已停用的分组显示“启用”；点击后直接恢复，无需二次确认。
- 请求进行期间禁用当前操作，防止重复提交。
- 请求失败时沿用页面现有错误提示区域展示后端错误。
- 请求成功后刷新分组列表；如果当前正在编辑同一分组，同时更新表单中的 `is_active`，防止随后保存旧表单时覆盖刚完成的切换。

## 运行时行为

现有后端行为保持不变：停用分组保留模型与 API Key 绑定，但不再出现在用户可选分组中，也不参与 API Key 请求路由。重新启用后原绑定继续生效。

- 停用接口完成数据库更新后才向管理端返回成功。
- 数据库更新成功后的新请求立即跳过停用分组，不依赖模型分组缓存过期。
- API Key 如果还绑定其他包含目标模型的启用分组，继续按原顺序使用其他分组；如果没有其他可用分组，请求返回模型不可用。
- 已经开始的 HTTP/SSE 请求和已经建立的 Realtime WebSocket 不强制中断。
- 已建立的 Responses WebSocket 在下一次 `response.create` 时重新选路，因此下一次调用立即受停用状态影响。
- 用户已打开的页面不做服务端推送刷新；页面重新获取数据后不再展示停用分组，实际 API 请求不受旧页面数据影响。

## 范围

- 修改管理端模型分组页面。
- 复用 `adminApi.toggleModelGroup`。
- 不修改数据库结构、模型分组绑定关系或路由规则。
- 不增加批量启停、定时停用或停用原因。
- 不增加连接注册表或强制终止进行中请求的机制。

## 验证

- 前端契约测试覆盖停用、启用、确认和当前表单状态同步。
- 运行相关前端测试、TypeScript 构建和 ESLint。
- 运行模型分组相关 Go 测试，确认现有后端行为未回归。
- 核对停用后的新请求、显式渠道授权和 Responses WebSocket 均重新读取分组状态。
- 启动本地前端并在浏览器中验证桌面页面，提供完成后的页面截图。
