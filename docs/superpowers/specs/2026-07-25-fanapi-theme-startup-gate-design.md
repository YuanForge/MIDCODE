# FanAPI 主题继承与启动配置门禁设计

## 背景

FanAPI（MidCode）当前会在各页面组件中分别调用 `useSiteSettings()`，并在公开配置返回前使用内置默认品牌。主题颜色固定在 `index.css` 中，后台没有主题色配置入口，公开设置接口也不返回 `theme_color`。

本次仅修改 FanAPI。OctoAPI 作为主题色计算和交互方式的参考，不修改其代码、配置或运行行为。

## 目标

1. FanAPI 后台可以配置主题颜色，前台亮色和暗色界面统一继承该颜色。
2. 首次加载时只请求一次公开站点配置。
3. 公开配置返回前不渲染业务页面，避免默认主题色和默认品牌闪现。
4. 加载阶段使用已确认的方案 B：中性灰几何加载状态，不依赖后端品牌或主题色。
5. 配置请求失败时提供明确错误和重试入口。
6. 后台保存主题色后当前页面立即应用，无需手动刷新。

## 非目标

- 不修改 OctoAPI。
- 不建立 FanAPI 与 OctoAPI 之间的运行时配置依赖。
- 不新增数据库表、列或迁移。
- 不调整认证、授权、支付、计费和其他业务行为。
- 不复制 OctoAPI 当前的 `GATEWAY / LLM / IMAGE / VIDEO` 加载动画。

## 配置与后端

主题色沿用 `system_settings` 键值存储，键名为 `theme_color`。现有管理员设置更新接口已经支持保存任意设置键，因此后端只需将 `theme_color` 加入公开设置白名单，使 `/public/settings` 可以返回该值。

主题色允许为空，表示使用 FanAPI 默认主题。非空值必须是 3 位或 6 位十六进制颜色。前端管理页面阻止无效值提交；公开接口返回异常值时，前端忽略该值并使用默认主题，禁止将未经验证的字符串写入 CSS。

配置优先级为：

1. `/public/settings` 返回的非空 `theme_color`。
2. `window.__FANAPI_ENV__.theme_color`。
3. FanAPI 内置默认主题。

后端配置保持主权，`env.js` 仅作为后端未配置主题色时的部署兜底。

## 前端架构

### 站点设置上下文

将现有 `useSiteSettings()` 收敛为一个全局 `SiteSettingsProvider`。Provider 在应用启动时请求一次 `/public/settings`，解析并保存所有公开配置。现有调用方继续通过 `useSiteSettings()` 读取设置，不再各自发起请求。

上下文公开以下状态：

- `settings`：已解析的站点配置，包括 `themeColor`。
- `status`：`loading | ready | error`。
- `loaded`：兼容现有调用方，等价于 `status === 'ready'`。
- `retry()`：失败后重新请求公开配置。
- `updateThemeColor()`：后台保存成功后立即更新当前主题。

### 主题色计算

新增共享主题模块，将一个合法基础色派生为亮色和暗色语义变量。覆盖范围仅限品牌相关令牌：

- 主按钮及交互态。
- 焦点环。
- 强调色。
- 侧栏选中态。
- 第一图表色。

成功、警告、错误等状态色不随品牌变化，避免语义混淆。派生颜色必须维持可读对比度；无效或空主题色会清除动态变量，恢复 CSS 默认值。

`index.css` 继续保留当前默认颜色，并通过 `var(--brand-*, <默认值>)` 接受动态覆盖。亮色和暗色模式分别使用对应变量。

### 启动配置门禁

应用根节点由 `SiteSettingsProvider` 包裹，并在路由之前增加配置门禁：

- `loading`：显示方案 B 的中性灰几何加载状态。它不显示站点名称、Logo 或后端主题色，也不渲染业务路由。
- `ready`：先在布局阶段写入主题变量和 SEO 元数据，再展示路由内容，避免默认主题闪现。
- `error`：显示简洁的“站点配置加载失败”提示和“重新加载”按钮，不显示几何动画。

不设置人为的最短加载时间。后端响应足够快时直接进入应用，避免为了展示动画而延迟首屏。

加载动画遵守 `prefers-reduced-motion`；用户减少动态效果时，呼吸环停止运动，但加载状态仍可识别。

## 管理后台交互

系统设置的“基本设置”区域新增主题颜色字段，复用与 OctoAPI 一致的交互：

- 可点击的颜色选择器。
- 十六进制色号输入框。
- 推荐颜色选项。
- 恢复默认操作。
- 无效颜色提示，并禁用保存。

保存仍使用现有管理员设置接口。保存成功后调用 `updateThemeColor()`，立即更新管理后台和共享站点主题。

## 错误与恢复

- 公开配置失败：不使用默认配置进入应用，保持错误页并允许重试。
- 重试期间：重新显示方案 B 的中性加载状态。
- 主题色无效：配置请求仍视为成功，只忽略无效主题色并采用默认主题。
- 管理后台保存失败：保留表单输入，显示现有错误提示，不修改当前主题。

## 测试与验收

### 后端测试

- `theme_color` 包含在公开设置白名单中。
- 公开设置响应不会扩大敏感配置暴露范围。

### 前端单元与契约测试

- 3 位和 6 位十六进制颜色可标准化，无效字符串被拒绝。
- 派生的亮色和暗色主色、前景色满足对比度要求。
- 动态变量不覆盖成功、警告和错误语义色。
- App 使用单一 Provider 和启动门禁。
- 加载状态不包含 OctoAPI 的 `GATEWAY / LLM / IMAGE / VIDEO` 文案。
- `theme_color` 解析、环境兜底和保存后即时更新均有契约覆盖。

### 浏览器验收

- 延迟 `/public/settings` 时，只显示中性几何加载状态，业务页面和默认品牌不可见。
- 配置返回后，主题变量已经写入，再显示登录页或业务页面。
- 亮色、暗色、桌面和手机视口均无主题闪烁、重叠或裁切。
- 请求失败时显示错误和重试；重试成功后进入应用。
- 后台修改主题色并保存后，当前页面立即更新；刷新后仍使用后端配置。
- 浏览器控制台无相关错误或警告。
